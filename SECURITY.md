# Security reporting

Keep credentials, authorization files, provider receipts and budget ledgers private.
Do not include them in public issues. Use GitHub private vulnerability reporting
for this repository when enabled; otherwise request a private reporting channel
from the organization without posting sensitive details.

The current supported candidate is 0.5.0rc1. Older archives remain historical,
not maintained provider integrations. No remediation deadline is promised.
Untrusted agents must run in a separate process with only public exports mounted;
a Python callback boundary is not a security sandbox.
